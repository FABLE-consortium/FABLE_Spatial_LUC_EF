# FABLE Spatial Land-Use Change Emission Factors

This repository contains a workflow to derive spatially explicit carbon stocks and land-use change emission factors for integration into the FABLE spatial modelling framework.

The workflow builds directly on the open-source [`mrorganic`](https://github.com/tscheypidi/mrorganic) and [`madrat`](https://github.com/pik-piam/madrat) R packages.

`mrorganic` provides the underlying methodology and data-processing workflow used here to estimate spatially explicit soil organic carbon (SOC), aboveground biomass carbon, and belowground biomass carbon stocks. `madrat` provides the reproducible data-processing, source-data management, caching, and aggregation framework on which `mrorganic` is built.

We gratefully acknowledge the authors and contributors of both packages for developing these tools and making their code and methodology openly available. The workflow developed in this repository would not have been possible without their work.

The main contribution of this repository is to:

- adapt the land-cover aggregation used for the carbon-stock calculations to land-use classes compatible with the FABLE spatial modelling framework;
- aggregate the resulting carbon stocks to the FABLE 50 × 50 km spatial grid; and
- derive spatially explicit emission factors associated with specific land-use transitions.


## 1. Workflow overview

The starting point of this workflow is the carbon-stock methodology implemented in `mrorganic`.

The main adaptation introduced in this repository is the reclassification of ESA CCI land-cover classes into land-use categories aligned with the FABLE spatial modelling framework. Separate mappings are used for SOC and biomass because the land-cover distinctions required for the two carbon pools differ.

The workflow then:

1. uses the `mrorganic` carbon-stock calculations with adapted ESA CCI land-cover mappings;
2. derives SOC, aboveground biomass, and belowground biomass carbon stocks by FABLE-compatible land-cover class;
3. aggregates these carbon stocks to the FABLE 50 × 50 km grid;
4. aggregates the results to country–ecoregion combinations where required; and
5. derives emission factors from the difference in carbon stocks between the initial and destination land uses.

For a transition from land use A to land use B:

```text
EF(A → B) = Carbon stock in A - Carbon stock in B
```

Positive values therefore represent a carbon loss associated with the transition, while negative values represent a carbon gain.

## 3. R environment

This project uses `renv` to manage R package dependencies.

The workflow was developed with **R 4.3.3**.

After cloning the repository, open the project from the repository root.

If `renv` is not already installed, install it with:

```r
install.packages("renv")
```

Then restore the project environment:

```r
renv::restore()
```

This installs the package versions recorded in `renv.lock`.

Once the environment has been restored, restart R before running the workflow.


# Recommended pathway: use the precomputed caches

This is the recommended option for most users.

Some of the underlying `mrorganic` calculations are computationally expensive and can take several hours. Precomputed `madrat` caches are therefore provided separately so that users do not need to repeat these calculations.

Users following this pathway **do not need to download the approximately 10 GB `madrat_data` source archive** described later in this README.


## 4. Download the precomputed caches

Precomputed caches are provided separately from the GitHub repository because of their size.

**[Download the precomputed FABLE carbon-stock caches](https://www.dropbox.com/scl/fi/n3ut47r0u4motnihzhxor/cache.zip?rlkey=x3frofh3ljqsekuuda9egnmtv&st=pauxmbye&dl=0)**

Download the ZIP archive and extract its contents into the `cache/` folder at the root of the repository.

The resulting structure should look approximately like:

```text
FABLE_Spatial_LUC_EF/
│
├── cache/
│   ├── cache_SOC_FABLE_v1/
│   └── cache_BIOMASS_FABLE_v2_urban/
│
├── R/
├── data/
└── ...
```

The cache versions correspond to the land-cover mapping versions defined in `R/00_setup.R`.

For example:

```r
soc_version <- "v1"
biomass_version <- "v2_urban"
```

The setup script automatically checks whether the expected cache versions are available.


## 5. Run the setup script

Run:

```r
source(here::here("R", "00_setup.R"))
```

The setup script:

- identifies the project root;
- defines project-relative paths;
- creates the required local working directories;
- configures the local `madrat` environment;
- defines the active SOC and biomass mapping versions;
- identifies the corresponding caches;
- defines the expected carbon-stock output files; and
- loads the packages required by the workflow.

The local `madrat` working directory is automatically defined as:

```text
FABLE_Spatial_LUC_EF/madrat_data/
```

No user-specific absolute path should need to be added to the scripts.


## 6. Generate or load carbon-stock results

Run:

```r
source(here::here("R", "01_carbon_stocks.R"))
```

This script defines the ESA CCI → FABLE land-cover mappings used for SOC and biomass.

SOC and biomass use separate mappings and therefore separate cache versions.

The workflow checks that the mapping associated with a version has not changed. If the mapping is modified, a new version name should be created in `00_setup.R`.

For example:

```r
soc_version <- "v2"
biomass_version <- "v3_revised_forest"
```

**Do not reuse an existing mapping version name after changing its mapping.**

If the corresponding carbon-stock `.rds` outputs already exist, they can be loaded directly. Otherwise, the calculation uses the corresponding precomputed cache.

The resulting carbon-stock objects include:

```text
soc_custom_FABLE_<version>.rds

biomass_aboveground_custom_FABLE_<version>.rds

biomass_belowground_custom_FABLE_<version>.rds
```

Using the precomputed caches avoids repeating the most computationally expensive parts of the `mrorganic` calculations.


## 7. Compute land-use change emission factors

Run:

```r
source(here::here("R", "02_emission_factors.R"))
```

This script:

- loads the saved SOC and biomass carbon-stock objects;
- converts the carbon-stock layers to spatial rasters;
- aggregates the carbon stocks to the FABLE 50 × 50 km polygon grid;
- calculates total biomass carbon stocks;
- aggregates carbon stocks to country–ecoregion combinations;
- computes transition-specific SOC and biomass emission factors;
- computes cell-level transition emission factors;
- generates diagnostic carbon-stock maps;
- generates global and country-specific transition maps;
- generates country transition matrices; and
- exports tables and R objects.

Each execution creates a timestamped output folder:

```text
output/
└── run_YYYYMMDD_HHMM/
```

For example:

```text
output/
└── run_20260817_1715/
```

This prevents a new execution of the workflow from overwriting results from an earlier run.

Each run also contains a `run_info.csv` file recording the mapping versions and carbon-stock input files used to generate the emission factors.


## 8. Country-specific maps

Country-specific maps are controlled through the `countries_to_map` vector in `02_emission_factors.R`.

For example:

```r
countries_to_map <- c(
  "IND",
  "BRA",
  "ZAF"
)
```

For each country listed, the script generates:

- individual maps for the different land-use transitions; and
- a faceted transition matrix showing the different transitions together.

The colour scale is kept consistent across countries to facilitate comparison.

Set:

```r
countries_to_map <- character(0)
```

to skip country-specific maps.


Once generated, the corresponding cache should be retained so that future runs using the same mapping do not need to repeat the expensive calculations.


## 12. Land-cover mappings

SOC and biomass intentionally use different ESA CCI aggregations.

The exact correspondence between ESA CCI `NB_LAB` codes and FABLE-compatible classes is defined in the custom mapping used by `01_carbon_stocks.R` and versioned through the `mapping_versions/` directory.

### SOC

The current SOC aggregation distinguishes:

```text
cropland
pasture
other
```

The SOC `other` class is a broad catch-all containing land that is neither cropland nor pasture.

### Biomass

The biomass aggregation distinguishes:

```text
cropland
pasture
forest
otherland
other
urban
```

The more detailed biomass classification is used because differences in biomass carbon stocks between these classes are relevant for estimating carbon losses or gains associated with land-use transitions.


## 13. Mapping and cache versioning

SOC and biomass mappings are versioned independently.

The general logic is:

```text
ESA CCI mapping
       ↓
mapping version
       ↓
dedicated madrat cache
       ↓
versioned carbon-stock output
       ↓
land-use transition emission factors
```

Mapping definitions associated with each version are stored under:

```text
mapping_versions/
```

If an existing mapping version is detected but the underlying mapping has changed, the workflow should stop rather than silently reuse the old cache.

A new mapping should therefore always receive a new version identifier.

This is particularly important because generating the carbon-stock caches can take several hours, while reusing an existing cache is much faster.


## 14. Aggregation to the FABLE 50 × 50 km grid

The carbon-stock calculations and the FABLE spatial model do not initially use the same spatial units.

The carbon-stock rasters are therefore spatially aggregated to the actual FABLE 50 × 50 km polygons contained in:

```text
data/grid50_equal_area.gpkg
```

The aggregation uses polygon-based extraction rather than sampling the carbon-stock value at the grid-cell centroid.

Carbon-stock values are calculated using area-weighted means of the underlying raster cells intersecting each FABLE grid polygon.

This is important because the source rasters are in geographic coordinates and the physical area represented by a raster cell varies with latitude.


## 15. Carbon pools and transition coverage

The workflow currently considers three carbon pools:

```text
soil organic carbon
aboveground biomass
belowground biomass
```

Not every FABLE land-use class has a separate estimate for every carbon pool.

In particular, the SOC classification is broader than the biomass classification.

The transition outputs therefore contain:

```text
ef_soc
ef_biomass_above
ef_biomass_below
ef_biomass
pools_covered
```

where:

```text
ef_biomass = ef_biomass_above + ef_biomass_below
```

The `pools_covered` variable identifies whether the transition emission factor contains:

```text
soc + biomass
biomass only
soc only
none
```

This distinction should be considered when using the emission factors downstream.

## 17. Large files and GitHub

Large source datasets, caches, and generated outputs are deliberately not tracked in this repository.

The following directories should remain excluded through `.gitignore`:

```text
madrat_data/
cache/
output/
```

The approximately 10 GB of `mrorganic` source data should **not** be committed to GitHub.

Instead:

- source data are distributed through the separate `madrat_data` archive;
- precomputed caches are distributed through the separate cache archive; and
- generated outputs remain local unless they are explicitly selected for publication.

The GitHub repository therefore contains the code, configuration, mapping definitions, spatial grid, and documentation required to understand and reproduce the workflow without storing the large underlying datasets.

For a reproducible analysis, retain:

## 20. FABLE

This workflow was developed for use with the spatial modelling work of the **FABLE Consortium (Food, Agriculture, Biodiversity, Land-Use and Energy)**.
